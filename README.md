# KIMS SMART FACTORY

생산 제품의 수량과 상태를 관리하고, 디바이스 채널의 입력·출력 상태를 실시간으로 확인·제어하는 웹 애플리케이션입니다. 생산 입력, 제품·채널 관리, 디바이스 제어와 예약 기능은 회원 등급에 따라 제공됩니다.

## 주요 기능

- 생산 현황에서 제품별 누적 수량, 작업 수량, 목표 수량, 진행률, 상태와 변경 정보를 조회합니다. 달성률은 작업 수량 ÷ 목표 수량으로 계산합니다.
- 6등급 이상 사용자는 생산 입력 화면에서 작업 수량 증감값을 입력하고 제품 상태를 변경할 수 있습니다. 양수는 누적·작업 수량에 더하고, 음수는 두 수량에서 뺍니다. 목표 수량은 이 화면에서 수정할 수 없습니다.
- 7등급 이상 사용자는 제품 관리 화면에서 누적 수량, 작업 수량, 목표 수량을 각각 설정·수정할 수 있습니다. 수량 입력에는 사유가 필요하며 변경은 이력에 저장되고 연결된 화면에 실시간 반영됩니다.
- 6등급 이상 사용자는 제품 리포트를 조회할 수 있습니다.
- 7등급 이상 사용자는 디바이스 채널 예약을 조회·등록·수정·중지·삭제할 수 있습니다. 반복 예약과 실행 결과를 확인할 수 있습니다.
- 7등급 이상 사용자는 제품 관리 화면에서 제품 등록·수정·삭제, 정렬과 사용 여부를 관리할 수 있습니다.
- 8등급 이상 사용자는 회원·디바이스·채널과 제품-채널 연결을 관리합니다.
- 디바이스는 WebSocket으로 서버에 연결되며, 채널 상태와 명령 결과를 웹 화면에 전달합니다.
- 제품-채널 연결을 설정하면 해당 채널이 실제 `ON` 상태 변경으로 처리될 때 연결 제품의 누적 수량과 작업 수량을 각각 1 증가시킵니다. 목표 수량은 변경하지 않습니다. 연결된 제품은 각각 증가하며, 반복되는 동일 상태 보고만으로는 보통 다시 증가하지 않습니다.
- 디바이스·채널 표시 상태는 `Visible` 또는 `Invisible`이고, 디바이스 동작 상태는 Enabled/Disabled로 관리합니다. Device 관리에서 Disabled로 바꾸면 Invisible도 함께 적용되고, Enabled로 복구하면 Visible로 돌아옵니다. Visible/Invisible만 별도로 바꾸면 Enabled/Disabled 상태는 변하지 않습니다. Invisible 디바이스·채널과 Disabled 디바이스는 일반 Device 보기·제어 화면에서 숨겨집니다. Disabled 디바이스는 서버 소켓 연결과 명령 전달이 중지되지만 예약·제품 연결 관리에서는 선택할 수 있습니다.
- 개인 설정은 회원별로 저장됩니다. 테마와 일부 보기 설정은 화면에 적용되며, 표시 항목을 숨겨도 서버 데이터나 제어 동작은 변경되지 않습니다.

## 회원 등급과 권한

등급은 1등급부터 10등급까지입니다. 기능별로 최소 등급을 적용하며, 높은 등급은 낮은 등급의 일반 업무 권한을 포함합니다. 3등급은 2등급과, 5등급은 4등급과 같은 업무 권한을 가집니다. 아래 표의 페이지 경로는 해당 기능의 대표 화면입니다. 보호 페이지와 변경 API는 해당 최소 등급을 검사하며, 기본 현황 조회나 예약 레이블 같은 읽기 전용 조회는 화면 제공에 필요한 범위에서 더 낮은 등급에도 허용될 수 있습니다.

| 등급 | 업무 권한 | 회원 관리 범위 |
| ---: | --- | --- |
| 1 | 생산 현황·디바이스 상태 조회, 회원정보, 개인 설정 | 회원 관리 기능 없음 |
| 2 | 1등급과 동일 | 회원 관리 기능 없음 |
| 3 | 2등급과 동일 | 회원 관리 기능 없음 |
| 4 | 2등급 권한 + 디바이스 출력 제어 (`/device-control.html`). 채널 출력의 수동 ON/OFF가 가능하며, 디바이스·채널 설정을 관리하는 권한은 아닙니다. | 회원 관리 기능 없음 |
| 5 | 4등급과 동일 | 회원 관리 기능 없음 |
| 6 | 4등급 권한 + 생산 입력 (`/product-control.html`)에서 작업 수량 증감과 제품 상태 변경, 제품 리포트 조회 (`/product-report.html`). 목표 수량과 제품 등록 정보는 이 화면에서 관리할 수 없습니다. | 회원 관리 기능 없음 |
| 7 | 6등급 권한 + 제품 관리 (`/product-admin.html`)에서 제품 등록·수정·삭제·정렬·사용 여부와 누적·작업·목표 수량 관리, 채널 예약 조회·등록·수정·중지·삭제 (`/device_schedule.html`) | 회원 관리 기능 없음 |
| 8 | 7등급 권한 + 회원 관리 (`/user-admin.html`), 디바이스·채널 관리 (`/device-admin.html`), 제품-채널 연결 (`/product-channel-link.html`), Device 리포트 (`/device-report.html`) | 1~7등급 회원 관리 가능, 최대 8등급 부여 가능 |
| 9 | 8등급과 동일한 업무 기능 | 1~8등급 회원 관리 가능, 최대 9등급 부여 가능 |
| 10 | 8등급과 동일한 업무 기능. 최초 관리자 계정의 기본 등급 | 1~9등급 회원 관리 가능, 최대 10등급 부여 가능 |

### 계정 상태와 승인

일반 업무 페이지와 API는 로그인, 계정 상태, 승인 여부와 기능별 최소 등급을 검사합니다. 생산 현황과 디바이스 상태 조회는 승인된 계정의 기본 기능이며, 회원정보는 로그인한 사용자가, 개인 설정은 정지되지 않은 계정이 이용할 수 있습니다. 신규 가입은 1등급 `PENDING`으로 시작하고, 관리자가 승인하면 1등급 `APPROVED` 계정이 됩니다.

8등급 이상은 승인 전에도 등급별 관리자 기능을 이용할 수 있지만, 정지 계정은 관리자 등급과 관계없이 업무 기능이 차단됩니다. 따라서 승인 예외가 계정 정지나 기능별 최소 등급을 우회하지는 않습니다.

### 회원 관리 규칙

회원 관리 화면과 관리 API는 8등급 이상만 사용할 수 있습니다. 관리자는 회원 목록에서 전체 회원을 확인할 수 있지만, 자신보다 낮은 등급의 회원만 수정·승인·정지·삭제할 수 있습니다. 관리 대상에게 관리자 자신의 등급까지 부여할 수 있지만, 같은 등급이 된 뒤에는 그 회원을 더 이상 관리할 수 없습니다. 본인 등급 변경과 본인 계정 삭제도 허용되지 않습니다. 새 회원을 승인하면 먼저 1등급이 부여되며, 필요한 경우 별도의 회원 수정에서 관리자의 등급 이하로 조정합니다.

메뉴와 버튼의 표시·활성화는 사용 편의를 위한 안내입니다. 예를 들어 4~6등급은 Device 제어 화면에서 다음 예약 정보를 레이블로 확인할 수 있지만, 예약 버튼은 사용할 수 없습니다. 예약 관리 페이지와 변경 API는 서버에서도 7등급 이상인지 다시 검사합니다. 최종 접근 제어는 서버가 로그인·계정 상태·승인 여부·최소 등급을 기준으로 수행합니다.

## 운영 흐름

### 최초 관리자와 회원

1. 서버와 DB를 준비하고 `MASTER_USERNAME`, `MASTER_PASSWORD`를 설정합니다.
2. 서버가 최초 관리자 계정을 생성합니다. 최초 계정은 승인된 10등급입니다.
3. 사용자는 회원가입을 신청하고, 관리자는 회원 관리 화면에서 승인과 등급을 설정합니다.
4. 실제 업무에 필요한 최소 등급만 부여합니다.

### 제품 수량과 상태

1. 7등급 이상 관리자가 제품 관리 화면에서 제품 코드와 누적 수량·작업 수량·목표 수량을 등록·수정합니다. 기존 제품의 각 수량은 별도로 설정할 수 있습니다.
2. 6등급 이상 사용자가 생산 입력 화면에서 추가 또는 차감할 작업 수량과 작업 내용을 입력합니다. 입력값은 누적 수량과 작업 수량에 함께 반영됩니다. 수량이 0 미만이 되거나 정수 최대값을 넘는 변경은 저장되지 않습니다.
3. 생산 현황에서 업데이트된 값을 확인합니다.

제품 상태는 `대기`, `생산중`, `수리중`, `완료`, `정지`를 사용합니다. 생산 입력 화면에서 상태를 변경할 수 있으며, 이전·신규 상태가 `product_quantity_history`에 함께 기록됩니다.

누적 수량은 기존 `product.quantity`를 그대로 사용하고, 작업 수량은 `product.work_quantity`, 목표 수량은 `product.target_quantity`로 보관합니다. 기존 DB 최초 적용 시 누적 수량은 보존하고 작업 수량을 현재 누적 수량과 같게 초기화하며, 이후 서버 재시작 때는 작업 수량을 다시 초기화하지 않습니다. 새 제품은 두 수량을 별도로 입력합니다.

누적·작업·목표 수량 변경과 제품 상태 변경은 `product_quantity_history`에 기록합니다. 이력에는 변경 시점의 수량 스냅샷, 이전·신규 제품 상태, 변경 사유·유형·사용자와 KST 시각이 포함됩니다. 수량 변경 트리거는 같은 트랜잭션에서 이력을 저장합니다. 이전 수량이나 상태는 과거 행에 소급해 만들어 넣지 않습니다. Device 생산 이력은 변경 사용자에 Device ID를 기록하고 사유는 비워 둡니다. 수동 생산 입력은 입력한 양·음수 증감량을 누적·작업 수량에 동시에 반영합니다.

### 제품과 채널 연결

1. 8등급 이상으로 `/product-channel-link.html`에 접속합니다.
2. 제품, 디바이스, 해당 디바이스의 채널을 선택해 연결을 등록합니다.
3. 현재 연결 목록에서 연결을 수정하거나 삭제할 수 있습니다.
4. 연결된 채널의 `ON` 처리 시 연결 제품의 현재 수량이 증가하는지 생산 현황에서 확인합니다.

한 채널에 여러 제품을 연결하면 그 채널의 `ON` 처리마다 사용 설정된(`product.is_enabled=1`) 연결 제품의 누적·작업 수량이 증가합니다. 사용 중지 제품은 생산 현황과 Device 자동 증가에서 제외되지만 제품-채널 연결 정보는 유지됩니다. 같은 제품·디바이스·채널 조합은 중복 등록할 수 없습니다. Invisible 디바이스·채널 여부와 제품 사용 여부는 별도 설정이며, Disabled 디바이스는 소켓 메시지를 보내지 않으므로 자동 증가가 멈춥니다.

### 디바이스와 예약

디바이스 관리에서 장치를 등록하고 Visible/Invisible 표시와 Enabled/Disabled 동작 상태, 채널 이름을 관리합니다. Disabled로 설정하면 Invisible도 적용하고 기존 소켓을 닫아 새 연결을 거부합니다. 다시 Enabled로 바꾸면 Visible로 복구되어 장치가 재접속할 수 있습니다. 표시 상태만 별도로 변경해도 동작 상태는 유지됩니다. **명령 전송 성공과 장치가 실제 출력을 적용한 것은 다르므로**, 장치 응답과 보고된 현재 상태를 확인합니다.

예약은 7등급 이상이 조회·설정할 수 있고 서버가 약 5초 간격으로 실행 시점을 확인합니다. Invisible 또는 Disabled 디바이스와 Invisible 채널도 예약 대상으로 선택할 수 있습니다. 조회 전용 채널도 예약으로 제어할 수 있으며, 웹에서 직접 ON/OFF하는 수동 제어는 계속 제한됩니다. Disabled 디바이스의 예약 명령은 큐에 보류되며 Enabled로 복구 후 장치가 재접속하면 전달됩니다. 예약 자체의 활성/비활성은 예약 실행 여부를 제어하는 별도 설정입니다. 예약이 명령 큐에 들어간 상태와 장치가 명령을 처리한 상태는 구분됩니다. 예약 관리에서 마지막 실행 상태와 장치 응답을 함께 확인합니다. 시간 기준은 한국 표준시(KST)입니다.

### 디바이스 채널 리포트

8등급 이상은 장치 관리의 `Device 리포트` 링크로 [리포트 페이지](public/device-report.html)에 접속합니다.

- `분석 항목 선택`에서 통계 6개와 그래프 8종을 개별 선택할 수 있습니다. 그래프는 ON · OFF 상태, ON 누적 횟수, ON 누적 시간과 분별·시간별·일별·주간별·월별 ON 전환 횟수입니다. 기본은 전체 선택이며 최소 한 항목이 필요합니다. 선택 변경 후 리포트를 다시 조회하면 화면과 PDF에 선택한 항목만 포함됩니다.
- 기존 ON·OFF 횟수는 조회 기간 안에 실제 시간이 존재하는 연속 상태 구간의 수입니다. 조회 시작 시 이미 유지 중인 상태도 1회 포함하며, 같은 상태의 반복 기록은 추가로 세지 않습니다. ON 누적 횟수 그래프는 ON 구간 시작마다 증가하며 마지막 값은 ON 횟수 통계와 같습니다. 새 기간별 ON 전환 횟수 그래프는 실제 OFF→ON 변경만 집계하므로, 최초 관측 ON이나 조회 시작 시 이미 ON인 상태와 반복 ON 기록은 더하지 않습니다. 이력이 없는 구간은 확인 불가, 일부 이력만 있는 구간은 확인된 기록 합계로 구분합니다.
- 기간별 집계는 KST 기준 매분 00초, 정시, 자정, 월요일 00:00, 매월 1일 00:00, 매년 1월 1일 00:00 경계에 맞춥니다. 월·연간은 실제 달력과 윤년을 따르고 조회 시작·종료에 걸친 구간은 선택 범위만 집계합니다. 분별 구간은 선택 채널 전체 합계 100,000개까지이며 초과 시 기간·채널 수를 줄이거나 분별 항목을 해제합니다.
- 시간 기준은 한국 표준시(KST)이며 시작 시각은 포함하고 종료 시각은 포함하지 않습니다. 미래 기간은 조회할 수 없고, 한 번에 최대 366일·변경 이력 100,000건까지 조회합니다. 초과 시 기간을 줄여야 하며 데이터를 임의로 잘라 집계하지 않습니다.
- 그래프 X축은 그래프 주기에 맞는 눈금과 라벨을 사용합니다. 분별·시간별은 월·일과 시각, 일별은 일, 주간별은 월요일 시작, 월별은 년·월을 표시합니다. 화면과 PDF는 같은 기간 경계 규칙을 사용합니다.
- `채널 PDF 다운로드`는 해당 채널을, `디바이스 PDF 다운로드`는 조회 시 선택한 채널만 채널 단위로 묶어 `.pdf` 파일로 직접 내려받습니다. 그래프가 많으면 그래프 제목 경계에서 페이지를 나눠 읽기 쉬운 크기를 유지하고 페이지별 장치·채널 코드를 표시합니다. 인쇄 창을 열지 않으며 PDF에는 한글, 그래프와 통계가 포함됩니다.
- `Excel 다운로드`는 조회 시 선택한 채널만 실제 `.xlsx` 파일로 내려받습니다. 채널 요약, 상태 구간, 상태 변경 이력과 시간별·일별·주간별·월별·연간별 ON 전환 횟수 시트를 포함하며, 분별 항목 선택 시 분별 시트도 추가됩니다. 기간별 시트는 횟수와 KST 시작·종료, 이력 확인 여부를 담습니다. 채널 선택을 바꾸면 리포트를 다시 조회한 뒤 다운로드합니다.
- 집계 기준은 저장된 **출력 상태**입니다. `총 전환 횟수`는 ON·OFF 구간 수의 합이 아니라 실제 상태 변경 횟수입니다. 같은 상태의 반복 보고나 상태가 바뀌지 않은 예약 완료 기록은 전환 횟수에서 제외합니다. 첫 관측 상태는 전환 횟수 없이 기준 이력으로 저장하지만, 이후 유지되는 상태 구간은 ON·OFF 횟수에 포함합니다. 통신이 끊겼을 때 실제 접점 상태는 검증할 수 없으므로 이 통계는 물리적 가동 시간을 보증하지 않습니다.
- 기존 장치별 1,000건 상태 이력 자동 삭제는 중단합니다. 이미 삭제되었거나 수집하지 않은 과거 상태는 복원할 수 없으며 `확인 불가`로 표시하고 ON/OFF 시간에 더하지 않습니다. 첫 관측 전 구간도 확인 불가입니다. 운영 시 DB 용량·백업 정책을 함께 관리하세요.

### 제품별 현황 리포트

6등급 이상은 생산 현황 또는 생산 입력 화면의 `제품 리포트` 링크로 [제품 리포트 페이지](public/product-report.html)에 접속합니다. 제품 리포트와 조회용 제품 목록은 6등급, 제품 관리 페이지와 관리용 목록·등록·수정·삭제 API는 7등급 이상으로 구분합니다.

- 조회는 최대 50개 제품, KST 기준 시작 포함·종료 미포함, 최대 366일·이력 100,000건입니다. 제품 선택은 처음에 모두 미선택이며 분석 항목은 전체 선택입니다.
- `분석 수량 기준`에서 누적 수량 또는 작업 수량을 선택합니다. 기본은 누적 수량입니다. 선택 기준은 초기·종료·증가 통계, 그래프, PDF, Excel에 동일하게 적용됩니다. 누적 기준은 `quantity`, 작업 기준은 별도 `work_quantity` 스냅샷을 사용합니다. 증가 수량은 종료와 초기의 차이이며 음수일 수 있습니다. 시간 구간별 작업량은 각 스냅샷의 양수 변화만 합산합니다.
- 초기 수량, 종료 수량, 증가 수량, 기준 수량 추이와 분별·시간별·일별·주간별·월별 작업 수량 그래프를 개별 선택할 수 있습니다. 분별은 매분, 시간별은 정시, 일별은 자정, 주간별은 월요일, 월별은 매월 1일 KST를 경계로 집계합니다. 분별 구간은 선택 제품 전체 합계 100,000개까지이며 초과 시 기간·제품 수를 줄이거나 분별 항목을 해제합니다.
- 제품별 PDF는 선택한 제품과 분석 항목만 포함하고 인쇄 창 없이 다운로드합니다. Excel에는 제품 요약, 선택된 기준의 수량 변경 이력, 제품 상태 변경 이력, 분별(선택 시)·시간별·일별·주간별·월별 작업 수량 시트를 포함합니다. 연간별 작업 수량 시트는 제공하지 않습니다.
- `product_quantity_history`와 제품 트리거는 수량 또는 상태 변경을 기록합니다. 상태 이력에는 변경 전·후 상태가 포함됩니다. 기존 행에 없던 상태 이력은 소급 생성하지 않으며, 서버 DB 계정에는 기존 권한 외에 `TRIGGER` 권한이 필요합니다.
- 누적·작업 수량의 기준 이력이 없으면 조회 기간의 첫 기록을 초기 기준으로 사용하고 Excel·화면에 이를 표시합니다. 수집 전 기간이나 자료가 없는 구간은 확인 불가로 구분합니다. 과거 데이터는 복원하지 않으므로 이력 테이블의 용량과 백업을 관리하세요.

## 설치와 실행

### 준비 사항

- Node.js와 npm
- MySQL 또는 MariaDB 데이터베이스
- 디바이스 펌웨어를 빌드할 경우 PlatformIO와 지원 보드 및 USB 드라이버

### 패키지 설치

프로젝트 루트에서 실행합니다.

```bash
npm install
```

### 데이터베이스 준비

서버의 `DB_NAME`은 **이미 존재하는 데이터베이스**를 가리켜야 합니다. 방법은 다음 중 하나를 선택합니다.

- 신규 `factory` DB: DB가 없는 상태에서 [schema.sql](schema.sql)을 한 번 실행합니다. 이 파일은 DB와 현재 테이블, 예시 제품 및 기본 디바이스·16개 채널을 생성합니다. `factory`가 이미 있으면 실행하지 마세요.
- 다른 이름의 빈 DB: DB를 먼저 생성하고 `DB_NAME`을 해당 이름으로 설정합니다. 서버가 필요한 테이블을 준비합니다. 예시 제품은 제품 관리 화면에서 등록합니다.
- 운영 중인 DB: 기존 DB를 백업하고 현재 스키마와 호환되는지 확인합니다. 서버 시작 시 `user_profile.username`을 `login_id`로, `device.device_id`를 `device.device_code`로 이전하고 관련 외래키를 복구합니다. `schema.sql`을 운영 DB에 재실행하거나, 구버전 테이블을 임의로 삭제하지 마세요.

서버는 테이블 준비와 제한된 호환 처리를 하지만 모든 과거 DB 구조를 자동 이전하지는 않습니다. 시작 로그에 스키마 오류가 있으면 기존 DB를 보존하고 백업·마이그레이션 계획을 확인하세요.

### 환경 파일 설정

프로젝트 루트에 `.env`를 만들고 환경에 맞게 설정합니다.

```dotenv
PORT=8080
DB_CLIENT=mysql
DB_HOST=localhost
DB_PORT=3306
DB_USER=factory_user
DB_PASSWORD=change_this_database_password
DB_NAME=factory
DB_POOL_SIZE=5

MASTER_USERNAME=master
MASTER_PASSWORD=choose_a_strong_master_password
MASTER_NAME=관리자

DEVICE_ID=DEVICE-D1-001
DEVICE_TOKEN=replace_with_random_device_token
```

DB 생성 권한이 필요한 신규 테이블 준비 단계에 충분한 권한을 부여합니다. DB 계정과 최초 관리자 비밀번호, 디바이스 토큰은 실제 값으로 바꾸고 저장소에 커밋하지 마세요.

### 서버 시작

```bash
npm start
```

기본 주소는 `http://localhost:8080`입니다. `PORT`를 바꾼 경우 해당 포트를 사용합니다. 서버는 DB 연결과 스키마 준비를 마친 뒤 요청을 받습니다. DB 초기화 실패 시 서버가 시작되지 않으므로 콘솔의 오류와 `DB_HOST`, `DB_PORT`, `DB_NAME`, 계정 권한을 확인하세요.

서버 세션은 프로세스 메모리에 저장되므로 서버를 재시작하면 사용자가 다시 로그인해야 합니다. DB의 제품·회원·디바이스 데이터는 정상 재시작으로 삭제되지 않습니다.

| --- | --- | --- |
| `PORT` | `8080` | 웹 서버 포트 |
| `DB_CLIENT` | `mysql` | `mysql` 또는 `mariadb` |
| `DB_HOST` | `localhost` | DB 호스트 |
| `DB_PORT` | `3306` | DB 포트 |

| `DB_POOL_SIZE` | `5` | DB 연결 풀 크기 |
| `MASTER_USERNAME` | 없음 | 최초 관리자 아이디. 설정 시 관리자 계정을 준비 |
| `MASTER_PASSWORD` | 없음 | 최초 관리자 비밀번호. 기본 비밀번호는 없으며 직접 설정해야 합니다. |
| `DEVICE_ID` | `DEVICE-D1-001` | 기본 장치 ID |
| `DEVICE_TOKEN` | 없음 | 기본 장치 인증 토큰 |
| `NODE_ENV` | 없음 | `production`이면 세션 쿠키에 `Secure` 적용. HTTPS 필요 |

장치 토큰은 서버에서 SHA-256 해시로 저장합니다. 서버와 펌웨어에 설정된 장치 ID·토큰이 일치해야 연결됩니다. 신규 장치는 장치 관리 화면에서 등록하고 발급된 토큰을 펌웨어에 설정합니다.

## 디바이스 펌웨어와 안전

펌웨어 파일은 [device/Device.ino](device/Device.ino)와 [device/Device.h](device/Device.h)입니다. PlatformIO 설정은 [platformio.ini](platformio.ini)의 `device_d1_r1` 환경이며 현재 보드 설정은 ESP8266 Wemos D1입니다.

```bash
pio run -e device_d1_r1
pio device list
pio run -e device_d1_r1 -t upload --upload-port COM6
pio device monitor --port COM6 --baud 115200
```

`COM6`은 예시이므로 실제 포트로 바꾸세요. Wi-Fi, 서버 주소, TLS 사용 여부, 디바이스 ID·토큰은 `Device.ino`의 설정 구역에서 대상 환경에 맞춥니다. 펌웨어에 비밀값을 넣을 때는 공개 저장소에 올리지 말고, 이미 노출된 값은 교체하세요.

각 장치는 `IS1`~`IS16`, `OS1`~`OS16`의 논리 채널을 사용합니다. `IStr`는 장치에서 서버로 보내는 문자열이고 `OStr`는 서버에서 장치로 전달하는 문자열입니다. 논리 16채널 전체가 실제 GPIO에 연결된 것은 아닙니다. 현재 스케치는 시험용 입력 IS1과 물리 출력 OS1을 사용하며 다른 채널의 물리 입출력은 별도 배선·GPIO 매핑이 필요합니다.

장치 연결은 `/ws/device?deviceId=...` WebSocket 경로를 사용하고, 토큰은 `Authorization: Bearer` 헤더로 전달합니다. TLS 사용 시 서버 인증서와 장치 TLS 구성을 확인합니다. 실제 설비에 연결하기 전에 부하를 분리하고 핀 번호, 출력 극성, 재부팅 동작을 충분히 시험하세요. 논리 출력 상태는 별도 피드백 센서가 없다면 실제 설비 동작을 증명하지 않습니다.

## 데이터 구조

[schema.sql](schema.sql)과 서버 초기화 코드는 다음 테이블을 사용합니다.

| 테이블 | 역할 |
| --- | --- |
| `user_profile` | 회원, `login_id` 계정명, 계정 상태, 권한, 비밀번호 해시. 앱/API 응답은 기존처럼 `username` 필드 사용 |
| `user_setting` | 회원별 화면·알림 설정 |
| `product` | 제품 코드, 누적·작업·목표 수량, 상태, 사용 여부(`is_enabled`)와 변경 정보 |
| `product_quantity_history` | 변경 시점의 누적·작업·목표 수량 스냅샷, 이전·신규 제품 상태, 사유·사용자·유형·시각. 제품 트리거가 기록 |
| `device` | 장치 등록·인증·접속 정보. 내부 숫자 PK는 `device_id`, 장치 식별 코드는 `device_code`, 표시 여부는 `is_visible`, 통신 사용 여부는 `is_enabled`입니다. API는 장치 식별 코드를 `device_id`로 반환합니다 |
| `device_channel` | 장치별 채널 상태·문자열·표시 및 제어 설정. 앱/API 표시 필드는 `is_visible` |
| `product_channel_mapping` | 제품과 출력 채널 연결 |
| `device_schedule` | 채널 예약과 실행 상태 |
| `device_command` | 출력 명령 큐와 ACK 상태. 예약 명령 여부는 `schedule_id` 유무로 판단 |
| `device_state_history` | 출력 상태 변경 이력과 `schedule_id` 기반 예약 출처 |

회원 삭제 시 개인 설정은 함께 삭제되고, 장치 삭제 시 해당 장치의 채널·명령·이력과 제품-채널 연결도 외래키에 의해 삭제됩니다. 제품 삭제 시 연결과 제품 수량 이력도 함께 삭제됩니다.

Device 표시 여부는 `device.is_visible`, 채널 표시 여부는 `device_channel.is_active`에 저장합니다. 기존 Device 테이블에 `is_active`가 있으면 서버 시작 시 값을 보존하며 `is_visible`로 컬럼명을 변경합니다. Device API와 관리 요청은 `is_visible`/`visible`을 사용합니다. Device의 `is_enabled`는 소켓 통신 여부이고, `device_schedule.is_enabled`는 개별 예약 실행 여부입니다. 예약 출처는 명령·상태 이력의 `schedule_id`로 식별합니다. 서버 시작 시 제한된 호환 마이그레이션으로 기존 스키마를 보정합니다.

## 문제 해결

| 증상 | 확인 사항 |
| --- | --- |
| 서버가 시작되지 않음 | DB 서비스 상태, DB 존재 여부, 접속정보·권한, 콘솔의 스키마 오류 확인 |
| 로그인 후 업무 화면 접근 거부 | 회원 승인·정지 상태와 해당 기능의 최소 등급 확인 |
| 제품 수량이 실시간 갱신되지 않음 | 브라우저 연결 상태와 실제 상태 변경 이벤트 확인. Invisible 제품은 생산 화면에서 숨겨지지만 DB 수량은 증가할 수 있음 |
| 채널 ON 후 수량이 증가하지 않음 | 제품-채널 연결과 실제 상태 변경 이벤트 확인. Invisible 디바이스·채널 상태는 증가를 막지 않음 |
| 디바이스가 연결되지 않음 | ID·토큰 일치, Wi-Fi, 서버 주소·포트, WS/WSS 설정 확인. Invisible 상태는 장치 인증을 막지 않음 |
| 명령 후 출력 상태가 변하지 않음 | 명령 큐 상태와 디바이스 ACK·실제 상태 보고를 구분해 확인 |
| 화면 상태와 실제 설비가 다름 | 상태가 논리값인지 확인하고 배선·출력 극성·피드백 센서를 점검 |

오류 문의 시 발생 시각, 화면 경로, 디바이스 ID, 채널, 오류 메시지를 기록하세요. 비밀번호·토큰·DB 접속정보는 로그나 문의 내용에 포함하지 마세요.
