Node.js, Express, MySQL/MariaDB, WebSocket으로 구성한 공장 생산 현황 모니터링 애플리케이션입니다.

## 주요 기능

- 회원가입 신청 및 관리자 승인
- 회원정보 수정과 비밀번호 변경
- 반려 회원의 재신청
- 회원 탈퇴 신청, 탈퇴 취소, 관리자 승인 후 완전 삭제
- 1~10등급의 계층형 회원 권한
- 승인 신청자 및 전체 회원 관리
- 관리자 메모 저장
- 제품코드·제품명·목표수량 관리
- 제품 추가·수정·삭제
- 생산수량 및 생산상태 실시간 관리
- 제품 상태: 대기, 생산중, 수리중, 완료, 정지
- 제품 수량/상태를 변경한 회원(변경자)과 최종 변경 시각을 현황판에 표시
- 회원별 개인 설정(알림음, 테마, 화면 표시, 날짜 형식, 변경자/변경일 표시 여부) DB 저장 및 자동 복원
- 정지된 계정과 삭제된 계정은 회원정보 화면 외 다른 페이지 접근 시 자동 로그아웃 후 로그인 화면으로 이동
- WebSocket을 이용한 현황판 실시간 갱신
- 비밀번호 `crypto.scrypt` 해시 저장
- MySQL 및 MariaDB 지원

### 관리 권한 규칙

- 8~10등급만 회원관리 페이지에 접근할 수 있습니다.
- 8~10등급만 신규 가입 신청을 승인할 수 있습니다.
- 관리자는 자기보다 낮은 등급의 회원만 수정, 상태 변경, 삭제할 수 있습니다.
- 관리자는 자기보다 높거나 같은 등급의 회원을 관리할 수 없습니다.
- 관리자는 자신의 계정과 권한 등급을 변경하거나 삭제할 수 없습니다.
- 회원 권한 등급을 변경할 때도 로그인한 관리자의 등급보다 낮은 등급만 부여할 수 있습니다.
- 6~10등급만 제품관리 페이지에 접근할 수 있습니다.
- 6~10등급만 Wemos 장치 관리 페이지에 접근할 수 있습니다.
- 2등급 이상만 생산수량·상태를 변경하고 Wemos 접점을 제어할 수 있습니다.
- 1등급도 승인된 계정이면 접점 상태 조회와 이력 조회가 가능합니다. 상태 조회만으로 접점을 제어할 수는 없습니다.
- 현황판, 접점 상태 조회, 생산 입력, 제품 관리 및 Wemos 기능은 승인된 활성 계정에서 사용할 수 있습니다. 회원정보는 로그인한 계정에서 확인할 수 있습니다.

## 회원 상태와 흐름

### 가입

1. 회원이 가입 신청을 제출합니다.
2. 계정은 `PENDING` 상태와 1등급으로 생성됩니다.
3. 8~10등급 관리자가 신청 내용을 확인합니다.
4. 승인하면 `APPROVED` 상태의 정식회원이 됩니다.

### 상태 종류

| 상태 | 설명 |
| --- | --- |
| `PENDING` | 가입 승인 대기 중 |
| `APPROVED` | 승인된 정식회원 |
| `REJECTED` | 가입 신청 반려. 회원은 정보를 수정한 뒤 재신청 가능 |
| `SUSPENDED` | 사용 정지 상태. 로그인과 회원정보 확인/수정은 가능하지만 그 외 페이지는 이용할 수 없음 |
| `WITHDRAWAL_PENDING` | 회원이 탈퇴를 신청했으며 관리자 처리를 기다리는 상태 |

### 정지 계정과 삭제된 계정 처리

- 정지된 회원도 로그인할 수 있으며, 로그인 직후 회원정보(`/profile.html`) 화면으로 안내됩니다.
- 정지된 회원이 현황판, 수량 입력, 제품 관리, 회원관리, 사용자 설정 등 회원정보 화면 이외의 페이지로 이동하면 서버가 세션을 즉시 삭제하고 로그인 화면으로 돌려보냅니다.
- 세션이 남아있는 상태에서 계정이 완전히 삭제된 경우에도 동일하게 처리되어, 다른 페이지 이동 시 자동으로 로그아웃되고 로그인 화면으로 이동합니다.
- 이 검사는 매 요청마다 데이터베이스의 최신 회원 상태를 확인하므로, 관리자가 정지·삭제 처리를 하면 즉시 반영됩니다.

### 탈퇴

- 승인된 회원은 회원정보 화면에서 탈퇴를 신청할 수 있습니다.
- 탈퇴 신청 후에는 `WITHDRAWAL_PENDING` 상태로 표시됩니다.
- 회원은 관리자 승인 전까지 `탈퇴 취소`를 할 수 있습니다.
- 관리자가 탈퇴를 승인하면 해당 회원 데이터가 데이터베이스에서 완전히 삭제됩니다.

## 실행 방법

### 1. 패키지 설치

```bash
npm install
```

### 2. 환경변수 설정

프로젝트 루트에 `.env` 파일을 만들고 데이터베이스와 최초 관리자 정보를 입력합니다. 자세한 형식은 아래 [환경변수](#환경변수)를 참고하세요.

### 3. 서버 실행

```bash
npm start
```

브라우저에서 다음 주소로 접속합니다.

```text
http://localhost:8080
```

## 환경변수

### 데이터베이스

```text
DB_CLIENT=mariadb
DB_HOST=데이터베이스 호스트
DB_PORT=3306
DB_USER=데이터베이스 사용자
DB_PASSWORD=데이터베이스 비밀번호
DB_NAME=실제로 존재하는 데이터베이스 이름
PORT=8080
WEMOS_DEVICE_ID=WEMOS-D1-001
WEMOS_DEVICE_PIN=D9
WEMOS_DEVICE_TOKEN=충분히긴URL안전난수
```

MySQL을 사용하는 경우 `DB_CLIENT=mysql`로 설정합니다.

Cloudtype MariaDB를 사용하는 경우 `DB_NAME`에는 MariaDB 서비스 이름이 아니라 실제 데이터베이스 이름을 입력해야 합니다. 존재하지 않는 이름을 입력하면 다음 오류가 발생합니다.

```text
Unknown database 'mariadb'
```

### 최초 상위 관리자

```text
MASTER_USERNAME=master
MASTER_PASSWORD=강력한비밀번호
MASTER_NAME=마스터 관리자
MASTER_REGION=대한민국
MASTER_COMPANY=관리자
MASTER_POSITION=마스터 관리자
MASTER_PHONE=010-0000-0000
MASTER_EMAIL=실제이메일@example.com
```

서버 시작 시 `MASTER_USERNAME` 계정이 없으면 10등급 상위 관리자로 자동 생성합니다. 이미 존재하는 계정이면 `MASTER`, 10등급, `APPROVED` 상태로 보정합니다.

## 데이터베이스

`factory` 데이터베이스가 없는 신규 환경에서 프로젝트의 `schema.sql`을 실행합니다. DB 생성 권한이 있는 계정으로 실행해야 하며, 데이터베이스 생성과 선택(`CREATE DATABASE factory`, `USE factory`)부터 회원·제품·개인 설정 및 Wemos 테이블과 초기 데이터 생성까지 한 번에 처리합니다. `Digital_input`, `Degital_output`을 포함한 모든 컬럼과 외래키는 처음부터 생성하며, 이후 `ALTER`로 추가하는 방식이 아닙니다. 이미 `factory`가 존재하면 오류가 발생하며, 기존 DB를 삭제하거나 덮어쓰지 않습니다.

이미 운영 중인 DB라면 서버가 시작할 때 `users`, `products`, `user_settings`에 필요한 컬럼을 확인하고 부족한 부분을 자동으로 `ALTER TABLE`로 추가합니다(`server.js`의 `ensureSchema()`). 현재 주요 테이블은 다음과 같습니다.

### `users`

회원 계정, 회원 상태, 권한 등급, 관리자 메모를 저장합니다.

주요 컬럼:

- `username`: 로그인 아이디
- `password_hash`: scrypt로 해시된 비밀번호
- `permission_level`: 1~10 권한 등급
- `admin_memo`: 관리자 전용 메모
- `status`: 회원 상태
- `created_at`: 가입일
- `updated_at`: 회원정보 수정, 재신청, 탈퇴 신청 등을 포함한 최종 변경일

### `products`

제품코드, 제품명, 생산수량, 목표수량, 생산상태를 저장합니다.

주요 컬럼:

- `updated_by`: 수량/상태/제품정보를 마지막으로 변경한 회원의 ID (`users(id)` 참조, 회원이 삭제되면 `NULL`로 설정)
- `updated_at`: 최종 변경 시각

현황판은 `users` 테이블과 조인하여 `updated_by`에 해당하는 회원 이름(변경자)을 함께 표시합니다.

### `user_settings`

회원별 개인 설정(알림음, 화면 테마, 표시 옵션)을 저장합니다. `user_id`가 `users.id`를 참조하는 1:1 관계이며, 회원이 삭제되면 설정도 `ON DELETE CASCADE`로 함께 삭제됩니다.

주요 컬럼:

- `user_id`: 회원 고유 ID (PRIMARY KEY, `users(id)` 참조)
- `sound_type`: 알림음 종류 (`bell`, `high`, `beep`, `low`, `soft`, `chime`, `alert`)
- `sound_volume`: 알림음 크기 (0~100 정수)
- `sound_enabled`: 알림음 사용 여부
- `theme`: 화면 테마 (`light`, `dark`)
- `display_mode`: 보기 모드 (`normal`, `compact`, `large`)
- `show_summary`, `show_target`, `show_rate`: 현황판 요약/목표수량/달성률 카드 표시 여부
- `show_updated_at`, `show_updated_by`: 현황판 표의 최종 변경일/변경자 열 표시 여부
- `date_format`: 날짜 표시 방식 (`ko-KR`, `iso`)
- `created_at`, `updated_at`: 생성일과 최종 변경일

기존 DB를 사용하는 경우에도 서버 시작 시 필요한 회원 컬럼, `products.updated_by`, `user_settings` 테이블/컬럼이 자동으로 마이그레이션/생성됩니다. 단, DB 사용자는 테이블과 컬럼을 변경할 권한이 있어야 합니다.

## 화면과 기능

### 로그인

- 승인 전 `PENDING` 회원도 로그인하여 회원정보를 수정할 수 있습니다.
- 반려된 `REJECTED` 회원도 로그인하여 정보를 수정하고 재신청할 수 있습니다.
- 정지된 `SUSPENDED` 회원도 로그인하여 회원정보를 확인할 수 있으나, 그 외 페이지로 이동하면 자동으로 로그아웃됩니다. 자세한 내용은 [정지 계정과 삭제된 계정 처리](#정지-계정과-삭제된-계정-처리)를 참고하세요.
- 로그아웃 시 서버 세션과 인증 쿠키를 삭제합니다.
- 로그인 화면으로 돌아갈 때 아이디와 비밀번호 입력값을 초기화합니다.

### 회원정보 수정

회원은 자신의 이름, 지역, 회사, 직위, 전화번호, 이메일을 수정할 수 있습니다.

- 비밀번호 변경 시 기존 비밀번호가 필요합니다.
- 새 비밀번호는 확인 입력값과 일치해야 합니다.
- 현재 권한 등급과 회원 상태를 확인할 수 있습니다.
- 취소하면 저장 전 정보로 복원됩니다.
- 회원 본인에게 관리자 메모는 표시되지 않습니다.

### 회원관리

8등급 이상 관리자만 접근할 수 있습니다.

- 승인 신청 대기자 확인
- 가입 신청 승인 및 반려
- 반려 회원 재신청 확인
- 탈퇴 신청 승인 및 반려
- 회원정보 수정
- 권한 등급 부여
- 회원 삭제
- 관리자 메모 작성 및 수정
- 회원별 가입일과 최종 변경일 확인
- 상태별 회원 수 확인

관리자 메모는 관리자 API와 관리자 화면에서만 조회됩니다. 회원 본인용 회원정보 API에는 메모가 포함되지 않습니다.

### 제품 관리

6등급 이상 관리자만 접근할 수 있습니다.

- `제품 목록 수정` 화면에서 제품코드, 제품명, 현재수량, 목표수량, 상태 수정
- 신규 제품 추가 시 제품코드, 제품명, 현재수량, 목표수량, 상태 입력
- 제품코드 중복 검사
- 제품 삭제
- 제품 변경사항을 현황판에 실시간 반영

제품 삭제는 데이터베이스에서 해당 제품 행을 완전히 삭제합니다.

### 수량 입력

2등급 이상 회원이 사용할 수 있습니다.

- 제품별 생산수량 입력
- 제품별 생산상태 변경
- 변경 결과를 모든 현황판에 실시간 반영
- 변경한 회원의 계정이 `products.updated_by`에 기록되어 현황판의 변경자 열에 표시됩니다.

## 사용자 설정

로그인한 모든 회원은 `/settings.html`에서 자신의 개인 설정을 변경할 수 있습니다. 비로그인 상태로 접근하면 로그인 화면으로 이동합니다.

### 설정 항목

- **알림 설정**: 알림음 사용 여부, 알림음 종류, 알림음 크기
- **화면 설정**: 밝은 화면 / 어두운 화면, 일반 / 간결 / 크게 보기
- **생산현황 표시 설정**: 요약 정보, 목표수량, 달성률, 최종 변경 날짜, 최종 변경자 표시 여부
- **날짜/시간 설정**: 한국식 날짜/시간 표시 여부

알림음 종류/크기 조절 UI는 현황판(`index.html`)이 아닌 `/settings.html`에서만 제공됩니다.

### 동작 방식

- 설정은 브라우저 `localStorage`가 아니라 회원 계정과 연결된 `user_settings` 테이블에 저장됩니다.
- 로그인하면 서버에서 본인의 설정을 조회하여 현황판(`index.html`)에 자동으로 적용합니다. 다른 PC나 브라우저에서 로그인해도 동일하게 복원됩니다.
- 설정을 저장하면 현재 화면(테마, 알림음 등)에도 즉시 반영됩니다.
- `GET /api/me/settings`, `PUT /api/me/settings` API는 항상 로그인 세션의 회원 ID를 기준으로 동작하며, 요청 본문에 다른 회원 ID를 넣어도 무시됩니다.
- 서버는 허용된 값(알림음 종류, 테마, 보기 모드, 0~100 범위의 볼륨, boolean 값)만 저장하며 잘못된 값은 `400` 오류로 거부합니다.
- 생산현황 데이터(WebSocket 브로드캐스트)는 기존과 동일하게 모든 접속자에게 공유되지만, 개인 설정은 본인에게만 적용되고 다른 회원에게 전달되지 않습니다.

## 운영 시 주의사항

- `.env` 파일에는 데이터베이스 비밀번호와 관리자 비밀번호가 포함되므로 Git에 커밋하지 마세요.
- Cloudtype 배포 후 환경변수를 변경하면 반드시 재배포하세요.
- DB 연결 실패 시 서버는 시작하지 않고 `DB 초기화 실패` 로그를 출력합니다.
- 회원가입 또는 로그인 오류가 발생하면 Cloudtype 실행 로그의 오류 코드와 메시지를 확인하세요.
- `Unknown column 'permission_level'` 오류가 발생하면 최신 코드를 재배포하거나 다음 SQL을 실행하세요.

```sql
ALTER TABLE users
ADD COLUMN permission_level TINYINT UNSIGNED NOT NULL DEFAULT 1;
```

- 기존 DB에 중복 이메일이 있으면 이메일 UNIQUE 인덱스 생성이 실패할 수 있습니다. 중복을 정리한 뒤 인덱스를 적용하세요.
- 회원 탈퇴 승인과 제품 삭제는 데이터베이스에서 복구할 수 없으므로 처리 전 대상 정보를 확인하세요.
- 관리자가 회원을 삭제하면 `user_settings`의 해당 회원 설정도 `ON DELETE CASCADE`로 함께 삭제되고, 해당 회원이 마지막으로 변경한 제품의 `updated_by`는 `NULL`로 바뀝니다.
- `schema.sql`은 `factory` 데이터베이스가 없는 신규 배포 전용입니다. 이미 DB가 존재하면 실행하지 말고, 서버를 재시작해 `ensureSchema()`가 자동으로 마이그레이션하도록 하세요.


## Wemos D1 R1 통합
- 제어 화면: `/wemos.html`
- 1등급 조회 화면: `/wemos-view.html`
- 1등급은 D8/D9/D10/D11 상태와 이력을 조회할 수 있으며, 2등급 이상은 `/wemos.html`에서 네 출력을 각각 ON/OFF로 조작할 수 있습니다.
- D8/D9/D10/D11 ON/OFF: **2등급 이상**만 가능
- 기존 Factory Monitor의 로그인/승인/권한 체계를 그대로 사용
- DB: 기존 `factory`에 Wemos 전용 3개 테이블과 핀별 상태 컬럼 추가
- WebSocket: Wemos 장치 `/ws/device`, 브라우저는 기존 WebSocket 서버 사용
- 웹/서버의 채널 표기는 물리 GPIO 대신 IS(입력 신호)와 OS(출력 신호)를 사용합니다. 실제 GPIO 매핑은 펌웨어 내부에서 처리합니다.
- Wemos 펌웨어: `wemos/WEMOSD1R1.ino`

### Cloudtype MariaDB
환경변수는 `DB_CLIENT=mariadb`, `DB_NAME=factory`를 사용합니다. 실제 Cloudtype DB 접속정보는 Cloudtype에서 제공한 값을 넣으세요. 비밀번호가 포함된 `.env`는 GitHub에 올리지 마세요.

Wemos 펌웨어의 `WIFI_SSID`, `WIFI_PASSWORD`, `SERVER_HOST`, `SERVER_PORT`를 실제 환경에 맞추세요. 서버의 `WEMOS_DEVICE_ID`와 `WEMOS_DEVICE_TOKEN`은 펌웨어의 `DEVICE_ID`, `DEVICE_TOKEN`과 같아야 합니다. `WEMOS_DEVICE_TOKEN`은 비워 둘 수 없으며, 충분히 긴 난수(예: `openssl rand -hex 32`)를 서버 환경변수와 펌웨어 양쪽에 동일하게 설정하세요. 펌웨어는 토큰을 WebSocket의 `Authorization: Bearer` 헤더로 전송합니다.

- 로컬 HTTP 서버: 펌웨어의 `SERVER_USE_TLS=false`, 보통 `SERVER_PORT=8080`
- HTTPS 전용 배포 서버: 펌웨어의 `SERVER_USE_TLS=true`, 보통 `SERVER_PORT=443`
- 액티브 로우 릴레이: 펌웨어의 `LAMP_ACTIVE_HIGH=false`

서버는 토큰이 설정되지 않았거나 장치가 올바른 토큰을 보내지 않으면 장치 WebSocket 연결을 거부합니다. 토큰은 URL에 포함되지 않으므로 URL 및 프록시 접근 로그에 노출되지 않습니다. HTTPS/WSS 배포에서는 인증 헤더도 암호화되지만, TLS 서버 인증을 위해 아래 인증서 검증 안내도 적용하세요.

### PlatformIO 빌드와 업로드

이 프로젝트는 PlatformIO의 `d1` 보드 환경(WEMOS D1 R1, ESP8266, 4MB Flash)을 사용합니다.

```bash
py -m platformio run -e wemos_d1_r1
py -m platformio device list
py -m platformio run -e wemos_d1_r1 -t upload --upload-port COM6
py -m platformio device monitor --port COM6 --baud 115200
```

업로드 포트 `COM6`은 예시입니다. `device list`에서 확인한 포트로 바꾸세요. 실제 설비 출력이 연결된 상태에서는 업로드 직후 각 접점 입력에 따라 대응 출력이 바뀔 수 있으므로 전원과 부하를 안전하게 분리한 후 업로드하세요.

기존 D9는 보드의 부팅 스트랩 조건에 영향을 줄 수 있으므로 기존 배선의 부팅 조건을 유지하세요. D8-D11도 보드의 실제 핀 매핑과 릴레이 입력 극성을 확인한 뒤 연결하고, 업로드 및 재부팅 중 출력이 안전한 상태인지 먼저 점검하세요.

`SERVER_USE_TLS=true`에서 CA 인증서나 지문을 지정하지 않은 현재 구성은 통신을 암호화하지만 서버 인증은 하지 않습니다. 외부 네트워크에서 WSS를 사용할 때는 고정 인증서 지문 또는 CA 검증을 추가해야 합니다.


## Wemos D1 R1 8채널 통신 구조

현재 Wemos 프로그램은 논리 채널 8개를 사용합니다.

| 채널 | 입력 상태 | 출력 상태 | Wemos → Server | Server → Wemos |
|---|---|---|---|---|
| 1 | IS1 | OS1 | IStr1 | OStr1 |
| 2 | IS2 | OS2 | IStr2 | OStr2 |
| 3 | IS3 | OS3 | IStr3 | OStr3 |
| 4 | IS4 | OS4 | IStr4 | OStr4 |
| 5 | IS5 | OS5 | IStr5 | OStr5 |
| 6 | IS6 | OS6 | IStr6 | OStr6 |
| 7 | IS7 | OS7 | IStr7 | OStr7 |
| 8 | IS8 | OS8 | IStr8 | OStr8 |

Wemos의 `state` 메시지는 `OutputSignal=OS1~OS8`, `OutputState`, `InputSignal=IS1~IS8`, `inputState`, `IStr`, `OStr`, `source`, `ip`를 포함합니다. 신호 이름은 채널 식별자이고 `OutputState`가 실제 출력의 `ON`/`OFF` 값입니다.
서버는 `wemos_contact_sets`에 채널 이름(`Digital_input`, `Degital_output`), 입력 상태(`input_state`)와 출력 상태(`current_state`), 문자열(`input_string`, `output_string`)을 각각 저장하고 브라우저에 WebSocket으로 전달합니다. 마지막 장치 IP는 `wemos_devices.last_ip`에 저장합니다.

### 입력 및 웹 제어 흐름

- **입력 변화**: IS1~IS8의 값이 50ms 동안 안정되면 대응 OS1~OS8을 같은 값으로 변경하고 `OutputSignal`, `OutputState`를 서버에 보고합니다. 이미 출력이 같은 값이어도 바뀐 입력 상태를 함께 보고합니다.
- **웹 버튼**: 브라우저가 장치 ID, `OutputSignal`, `severSignal="ON"/"OFF"`를 서버에 보냅니다. 서버는 인증·권한 확인과 명령 저장 후 디바이스로 전송합니다.
- **디바이스 명령 처리**: 채널별 `severSignal`에 요청값을 보관하고 실제 OS에 적용한 뒤, 실제 `OutputState`를 ACK 및 상태 보고로 전송합니다. 같은 상태의 요청도 상태 보고를 예약합니다.
- **웹 화면 반영**: 서버가 디바이스의 `OutputState`를 DB에 저장하고 상태 이벤트로 전달하면 현재 OS 표시와 ON/OFF 버튼 색상·선택 상태가 변경됩니다. 요청 저장·전달 알림만으로는 실제 상태를 변경하지 않습니다.
- **우선순위**: 마지막으로 처리된 입력 변화 또는 웹 명령이 출력에 적용됩니다. 웹 제어는 IS 입력값을 바꾸지 않으며, 이후 입력이 다시 변하면 입력값이 출력을 갱신합니다.

DB 및 조회 API의 입력·출력 채널 필드는 `Digital_input`, `Degital_output`을 사용합니다. 기존 DB의 `input_pin`, `output_pin`은 서버 재시작 시 데이터와 인덱스를 유지하면서 자동으로 이름을 변경합니다. WebSocket 송신은 Wemos·서버·브라우저 모두 `InputSignal`, `OutputSignal`을 사용합니다. 서버는 이전 펌웨어 및 브라우저의 `inputPin`, `pin`을 수신 호환용으로만 허용하며, 새 메시지에는 이전 필드를 넣지 않습니다. 이력·명령 테이블의 `pin_name`은 기존 데이터 저장 컬럼명으로 유지합니다.

### 장치 → 서버 메시지

| type | 주요 필드 | 서버 처리 |
| --- | --- | --- |
| `hello` | `deviceId`, `OutputSignal`, `inputs`, `outputs` | 인증된 장치의 IS1~IS8/OS1~OS8 채널 등록, 연결 상태 알림, 대기 명령 전송 |
| `state` | `deviceId`, `OutputSignal`, `OutputState`, `InputSignal`, `inputState`, `source`, `IStr`, `OStr`, `ip` | 입력·출력 상태와 문자열 저장, 실제 출력 변경 이력 기록, 실시간 전달 |
| `channelString` | `deviceId`, `OutputSignal`, `InputSignal`, `IStr` | 입력 문자열만 갱신, 기존 출력 문자열과 상태 유지 |
| `ack` | `deviceId`, `commandId`, `OutputSignal`, `OutputState`, `success` | 명령의 장치·채널·상태 확인 후 성공/실패 기록. ACK에 없는 입력 정보는 유지 |

`sendString`은 `IStr`의 호환 필드, `receiveString`은 `OStr`의 호환 필드입니다. 장치 메시지는 인증 완료 후 수신 순서대로 처리합니다. `CLIENT` 출처의 상태 보고도 입력 상태와 문자열을 반영하며, 출력 상태가 그대로이면 기존 변경자와 이력을 유지합니다.
이전 장치의 `state`도 수신 호환용으로 허용하지만 `OutputState`가 있으면 우선 사용합니다. 서버의 브라우저 상태 이벤트에는 `OutputState`와 기존 화면 호환용 `state`를 함께 포함합니다.

### 서버 → 장치 명령

브라우저에서 출력 제어를 하면 서버는 다음 형식으로 Wemos에 명령을 전송합니다.
서버 → 장치 `command` 메시지의 출력 문자열은 `OStr` 하나로만 전송하며, 중복 필드 `receiveString`, `outputString`은 포함하지 않습니다. 기존 펌웨어의 수신 호환 처리와 브라우저 알림·명령 이력의 데이터 형식은 유지합니다.

```json
{
  "type": "command",
  "deviceId": "WEMOS-D1-001",
  "commandId": "UUID",
  "OutputSignal": "OS1",
  "InputSignal": "IS1",
  "severSignal": "ON",
  "OStr": "MOTOR_ON"
}
```

기존 V0의 `D8/D9/D10/D11` 명령도 각각 `OS1/OS2/OS3/OS4`로 호환 변환됩니다.

접점 제어 화면에서 채널별 `OStr`를 입력하고 ON/OFF를 누르면 상태와 문자열이 같은 명령으로 전송됩니다. 1등급 조회 화면에는 제어 버튼과 문자열 입력 필드가 없습니다. 기존 회원·제품·설정 API와 제어 권한은 유지합니다.

현재 펌웨어는 빈 `OStr`를 받으면 기존 문자열을 유지하므로, 서버도 문자열이 비어 있는 제어 요청에서는 마지막 저장된 문자열을 사용합니다. 문자열만 바꾸려면 현재와 같은 ON/OFF 상태로 명령을 보낼 수 있으며, 이 경우에도 ACK와 상태 보고로 동기화합니다.

현재 펌웨어는 실제 GPIO 대신 논리 IS/OS 변수를 사용합니다. 실제 DI/DO 배선의 읽기·쓰기 코드는 별도로 연결해야 합니다. 펌웨어 업데이트 후 입력 변화가 출력을 자동 변경하므로 실제 설비에서 검증할 때에는 부하를 분리하고 안전한 상태에서 확인하세요.

기존 DB는 서버 재시작 시 `input_state`, `last_ip` 등 누락된 컬럼을 자동 추가합니다. `schema.sql`은 신규 DB에만 사용하세요. 펌웨어의 `DEVICE_ID`를 서버 환경변수와 동일하게 설정하거나 장치 관리에서 해당 ID를 등록하고 발급된 토큰을 펌웨어에 설정해야 합니다.
